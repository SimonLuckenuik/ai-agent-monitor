SmartClock-OSS 1.3.2 says more about **why the clock cannot join your WiFi**: a failed join now comes with the code the router or WiFi chip reported, and the settings page explains it.

## Download

**`SDPro_SmartClockOSS_v1.3.2.bin`**: one file for both the stock update page and our own. Keep the file name: the stock page only accepts names starting with `SDP`. It contains no WiFi details.

SHA-256: see `SHA256SUMS.txt` attached to the release.

## Upgrading

- **From 1.3.1, 1.3.0, 1.2.0 or 0.1.2:** install it from the **Firmware update** card. Your settings and photos stay.
- **From 0.1.1 or earlier:** the settings page and setup network now ask for the clock's password. On the sign-in page, press **Show the password on the clock** (see the [0.1.2 notes](https://github.com/michaeldale/smartclock-oss/releases/tag/v0.1.2)).

## New

- **WiFi disconnect codes** ([#2](https://github.com/michaeldale/smartclock-oss/issues/2)). When the clock cannot join, the setup screen adds the code, for example "Can't join: no answer (15)". The settings page explains it, for example:
  - 15 or 204: the password handshake timed out; check the password.
  - 202: authentication failed; check the password.
  - 201: the network was not found.
  - 20: unsupported security mode; use WPA2 rather than WPA3-only.
  - 203: the router refused the connection.

  If your clock still will not join, please open an issue with the code it shows and your router's WiFi settings (band, security mode, channel).

## Known limitations

- The disconnect codes have been built and tested on the PC but not yet confirmed on a clock.
- Only the GeekMagic SD Pro is supported. Other models, such as the SmallTV Ultra, use different boards.
- MQTT has still not been tested against a real broker and Home Assistant.
