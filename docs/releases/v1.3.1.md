SmartClock-OSS 1.3.1 fixes WiFi setup: **Connect & restart** now works on phones, where it could do nothing at all.

## Download

**`SDPro_SmartClockOSS_v1.3.1.bin`**: one file for both the stock update page and our own. Keep the file name: the stock page only accepts names starting with `SDP`. It contains no WiFi details.

SHA-256: see `SHA256SUMS.txt` attached to the release.

## Upgrading

- **From 1.3.0, 1.2.0 or 0.1.2:** install it from the **Firmware update** card. Your settings and photos stay.
- **From 0.1.1 or earlier:** the settings page and setup network now ask for the clock's password. On the sign-in page, press **Show the password on the clock** (see the [0.1.2 notes](https://github.com/michaeldale/smartclock-oss/releases/tag/v0.1.2)).

## Fixed

- **Connect & restart did nothing on phones.** After you join the clock's setup network, a phone usually opens the setup page in its sign-in window, and those windows block confirmation dialogs. The button asked for confirmation first, so nothing happened and the clock stayed on the setup screen. It now saves your network and restarts straight away. If you could not get your clock onto WiFi before ([#2](https://github.com/michaeldale/smartclock-oss/issues/2)), please try again with this version.
- **Clocks built from source keep their WiFi.** A clock that only joined through the network in `secrets.ini` now saves it the first time it joins, so installing a release image later does not leave it on the setup screen.

## Known limitations

- The photo-time switch and the WiFi failure reasons from 1.3.0 have not yet been tried on a clock.
- MQTT has still not been tested against a real broker and Home Assistant.
